# Contributing to CalmLinks

Thank you for helping improve CalmLinks. Please keep changes small, focused, and consistent with its calm, dependency-free approach.

## Report a bug

Use the bug report template and include clear reproduction steps, expected behavior, browser, device, viewport size, CalmLinks version, and screenshots when useful. Check existing issues before creating a new one.

## Suggest a feature

Use the feature request template. Explain the problem first, then describe the proposed solution and alternatives. Prefer improvements that keep CalmLinks static and dependency-free.

## Submit a pull request

1. Fork the repository and create a short, descriptive branch.
2. Make one focused change.
3. Do not add a dependency without discussing it in an issue first.
4. Test by opening `index.html` directly and through a local or hosted subfolder.
5. Test at mobile and desktop widths.
6. Check keyboard navigation, visible focus, heading order, link text, and basic color contrast.
7. Update documentation when behavior or customization guidance changes.
8. Open a pull request and complete the checklist.

## Commit style

Use short, imperative commit messages:

```text
Fix mobile navigation focus
Update deployment instructions
Improve project link contrast
```

Avoid mixing unrelated changes in one commit or pull request.
